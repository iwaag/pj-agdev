## Diagnosis

The gateway does not persist a transcript, so the same prompt was replayed
once directly through `role_run.run_role` with `transcript=` set. That replay
**succeeded** (8 turns, 38 s, `outcome: done`) and created Plane issue
`Draft the project README`. The transcript shows why the two runs differ:

- The local model first invents absolute paths and a non-existent workdir
  (`agautolab/front` instead of `agent/front`), burning three turns on
  `File not found` and `NotFound: FileSystem.access` errors.
- On the successful replay it recovers at turn 4 (`pwd`, then `find`), reads
  the chat log, runs `uv run new_mission.py --help`, and registers the mission.
- On the live run it never recovered inside its turn budget and ended with tool
  calls but no text part. `opencode` exits 0 in that case, so `run_harness`
  classifies it as `produced no output` and the gateway returns 502.

This is model behaviour under `profile=local`
(`ollama/qwen3.6:35b-a3b-coding-nvfp4`), not broken wiring — the same prompt,
harness, cwd and permissions succeed on retry. The report9 prompt hardening
(`785a0dd`) reduced this failure but did not remove it: the model still ignores
"you are already running in the front workspace" and guesses absolute paths
first.

## Observations worth acting on later (not done here)

- A front run that ends with tool calls and no final text is a total loss: the
  listener neither retries nor writes anything back to the topic, so the human
  sees silence. A single retry, or a failure notice via `topic_write`, would
  make the outcome visible.
- `/window` keeps no transcript, so every diagnosis requires replaying the run
  by hand.
- Switching the front profile to `sonnet` remains the untried separation of
  "model problem vs prompt problem" for this specific failure.
