# 人間×エージェント協調アイディア集

前提: 人間だけができる操作 = GUI 限定機能（Inspire Me / Song Generator、
Music Enhancer、エクスポート、インポート、FX、ボーカルパラメータ、録音、
プロジェクト保存/読込、クレジット消費の承認）。エージェントは surface 1.0 の
読み書き＋キャッシュ抽出。同じプロジェクトを共有して作業する。
確信度「できるかも」レベルを含む。

## 生成キットとの分業

1. **Inspire Me 下ごしらえ＋後処理係**
   人間が Song Generator を GUI で1回実行 →
   エージェントが結果のトラック/クリップ/ノートを全部読み出して構造分析、
   歌詞の差し替え、キー/テンポ調整、別歌手での歌い直しまで面倒を見る。
   「生成は人間のワンクリック、磨きはエージェント」という分業。

2. **生成前ブリーフィング資料の自動作成**
   Inspire Me に入れるプロンプトやパラメータの候補をエージェントが提案し、
   実行後の結果をまた読み取って「前回との差分レポート」を作る。
   人間はクリックと判断だけ。

## エクスポート不能の穴埋め

3. **「エクスポートだけお願いします」ワークフロー**
   エージェントが曲を完成させて `problem/依頼メモ` を書き、人間が GUI で
   正式エクスポートして所定フォルダに置く。キャッシュ抽出（非公式）を
   使わない品質保証ルート。逆に急ぎはキャッシュ抽出、正式版は人間、の二段構え。

4. **人間の演奏/録音素材への歌詞乗せ**
   人間が GUI で録音 or オーディオをインポート → エージェントがその
   Audio クリップの位置・長さを読んでボーカルトラックを設計・打ち込み。
   （オーディオの中身解析はキャッシュ/外部ツール併用でできるかも）

## 制作セッションの協調

5. **セッション・アシスタント（DAW の助手席）**
   人間が聴きながら「サビもう一回」「2番の頭から」と言うと、エージェントが
   marker seek / loop set / playback / solo・mute を操作する。
   人間は両手をキーボード（楽器の方）に置いたまま。

6. **テイク審査会**
   エージェントが候補メロディを別トラックに並べて打ち込み、順に solo +
   再生して聴かせる。人間が「2番目」と言えば他を削除して本採用。
   採用理由をエピソードログに記録して次回の作曲傾向に反映。

7. **歌詞ペアライティング**
   人間が日本語詞を書く → エージェントがモーラ分解・音数チェック・
   かな割当・打ち込みまで担当。「ここ字余りです、候補3つ」の逆提案も。
   sentence モード G2P の弱点を人間+エージェントで完全に回避する。

8. **ボーカルパラメータの指差し調整**
   パラメータ編集は GUI 限定なので、エージェントが「〇小節目のこのノート、
   ビブラート弱めが良さそう」と tick 位置付きで指示書を作り、人間が
   スライダーを動かす。marker seek で該当箇所に自動ジャンプさせて誘導。

9. **ハモリ・コーラス設計**
   人間がメインメロディを確定 → エージェントが3度/6度ハモリや対旋律を
   計算して別トラックに打ち込み、歌手も別ボイスをロード。人間は
   バランス（gain/pan は CLI 可）と最終判断。

## 発見・選定系

10. **ボイス・スカウティング会議**
    エージェントがコミュニティカタログを巡回してショートリストを作成、
    人間が試聴して collect を承認（collect 自体は CLI でも可能だが、
    ライブラリを汚す判断は人間に残す）。

11. **リファレンス曲の耳コピ分担**
    人間が原曲を聴いてコード進行とテンポ感をメモ → エージェントが
    tempo set / timesig set / ノート打ち込みで再現稿を起こす →
    人間が GUI で細部修正。ビート解析（GUI の tempo analyze）は人間側。

## 運用・学習系

12. **クレジット執行の承認フロー**
    将来 generative surface が公開されたとき用の型: エージェントが
    生成計画（回数×クレジット見積り）を提示 → 人間が承認 → 実行。
    credit.topup 系は常に人間。今から agforge の依頼テンプレに
    「承認ゲート」を用意しておくと移行が楽かも。

13. **制作ログの自動記録係**
    人間が GUI で作業している間、エージェントが定期的にプロジェクト状態を
    読み出して差分ジャーナル（いつ何トラックが増えたか、ノート数の推移）を
    記録。後から「あの時点に戻したい」の復元材料 & エピソードレポートの種。

14. **Failure Farming の実験台**
    「エクスポートして」等、わざと surface 外の依頼をエージェントに投げ、
    どう人間へエスカレーションするかを観察して ENT エピソード化。
    人間⇔エージェントの引き継ぎ プロトコル（依頼メモの書式、通知経路）を
    ここで育てる。

15. **上達コーチ（逆方向の協調）**
    エージェントがプロジェクトを読んで「このクリップ、ノートが拍頭から
    ずれてます」「テンポカーブが不連続です」と人間の打ち込みをレビュー。
    人間が主役、エージェントが校閲という向きも成立する。
