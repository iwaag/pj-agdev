# Candidate next turns

These are alternatives, not a committed sequence.

## Roll out the workflow to agautolab1

Publish the agautolab submodule state to the agstudio Gitea remote, deploy with
the existing Ansible controller path, and prove node-source freshness plus the
projects route before adding agautolab1 to the supported write scope.

## Start missions and jobs from agdevworld

Grow the conversational path from profile maintenance into starting a scoped
autolab mission or job, then render the accepted mission, live progress,
approval waits, and terminal evidence in the same view.

## Per-job profile override at submission

Let a user choose a one-run coding profile when starting a job while keeping
the project profile as the durable default. Make the precedence visible in the
job card and detail view.

## Authenticate gateway writes

Replace the experimental zero-auth node window with an authenticated channel
that preserves the single conversational entrance and keeps deterministic
reads cheap.

## Prove deployed-node source freshness

Expose and compare the deployment source commit with the node checkout/image
commit. Show stale nodes in agdevworld before a user trusts capabilities that
exist only in a newer checkout.

## Derive autolab nodes from cluster intent

Register autolab service placement in nintent and derive the agdevworld node
picker from cluster state instead of the hand-maintained `AUTOLAB_NODES` list.

## Preserve unrelated role selections during conversational edits

Failure-farm profile rewrites that change only one role, teach the front card
to inspect and preserve all unrequested keys, and add a live or fixture-backed
regression proof without replacing the conversational write with a script.

## Improve dense autolab layout

Separate or paginate project and job sections so nodes with dozens of jobs keep
readable cards on desktop and mobile while retaining the current overview.
